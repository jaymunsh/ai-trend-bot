    굵은 제목과 모바일 2~3줄 목표의 핵심 요약, 대표 원문 링크와 외 N곳으로 전달합니다. 최대 50건까지 허용하지만 기준에 맞는 소식이 없으면 보내지 않습니다.

    반영

조금 더 알아보기

기사가 몇 개씩 오나요? +

발송량은 가변입니다. 조용한 회차는 0건일 수 있고, 중요한 사건이 많은 날은 더 많이 보냅니다. 정규 실행의 상한 50건은 목표치가 아니라 폭주 방지선입니다.

요약은 무엇을 보고 만드나요? +

선별한 기사의 본문을 trafilatura로 추출해 Gemini에 전달합니다. 실패하면 RSS 티저로 요약합니다. 현재 모델 기본값은 gemini-3.1-flash-lite이며, 원문 링크를 함께 제공합니다. 요약은 원문을 대체하는 사실 검증 결과가 아닙니다.

이미 보낸 소식은 어떻게 구분하나요? +

발송한 URL의 해시로 같은 기사를 제외합니다. URL이 다른 반복 보도는 최근 14일에 보낸 사건 요지를 참고해 Gemini가 판정합니다. 병합한 기사의 출처 URL은 내부 기록에 보존하고 알림에는 대표 링크 하나와 외 N곳을 표시합니다. 중요한 새 사실이 있는 후속 보도는 남길 수 있으며, 모든 사건 중복을 완벽하게 막는 방식은 아닙니다.

수집이나 실행이 실패하면 어떻게 되나요? +

피드 실패는 해당 출처만 건너뜁니다. Gemini의 일시적인 429·5xx 응답은 재시도합니다. miniPC가 내려가거나 모델 요청이 끝내 실패하면 그 회차는 전달되지 않습니다. 다음 회차에서 피드에 남아 있는 최근 48시간의 미발송 항목을 다시 후보로 봅니다. 정시까지 준비가 끝나지 않으면 완료 직후 보냅니다.

Threads도 수집하나요? +

공식 Threads API 경로는 비활성화되어 있습니다. 현재는 RSSHub를 경유하는 @choi.openai 피드 하나가 RSS 수집처에 포함되어 있습니다. 외부 RSSHub의 상태와 형식에 영향을 받으며 현재 조회가 실패하고 있습니다. 별도 서버를 추가해 복구하지 않고, 실패한 회차에는 해당 출처만 건너뜁니다.

GitHub Pages에서 봇도 실행되나요? +

GitHub Pages에는 이 정적 소개 페이지를 올릴 계획입니다. 기사 수집과 Telegram 발송은 miniPC의 Python 프로그램이 담당합니다. 소개 페이지에는 API 키나 운영 상태 파일을 포함하지 않습니다.

운영 방법과 구현 코드는 어디서 보나요? +

저장소와 README에 설정, 실행, 장애 점검 방법이 정리되어 있습니다. uv run ai-trend-bot run --dry-run으로 실제 발송 없이 선별 결과를 확인할 수 있습니다.
