01

현재 구현 상태

수집부터 중복 제거, AI 요약, 텔레그램 발송, 예약 실행까지 한 사이클이 완성되어 있습니다.

활성 수집처8개공식 6 · 연구 1 · 커뮤니티 1
하루 실행3회08:17 · 14:17 · 20:17 KST
하루 상한45건회차별 최대 15 · 15 · 15건

완성된 기능

  • RSS 수집과 출처별 순환 선별
  • URL 해시 기반 중복 제거
  • Gemini 한국어 번역·3단 심층 요약
  • 텔레그램 메시지 묶음 발송
  • GitHub Actions 예약 실행과 캐시

현재 운영 모드

실제 자동 실행은 RSS 뉴스 중심입니다. Threads 수집 코드는 계정 피드, 자기 답글 결합, 키워드 검색까지 구현되어 있지만 Meta 권한 검수 전까지 설정에서 꺼져 있습니다.

02

처리 구조

각 단계가 실패 범위를 좁게 유지하도록 분리되어 있으며, 한 출처가 실패해도 가능한 나머지 출처는 계속 처리합니다.

03

운영 일정

한국 시간 기준 하루 세 번 실행합니다. GitHub Actions의 UTC cron은 각각 23:17, 05:17, 11:17로 저장되어 있습니다.

  1. 08:17아침 브리핑 · 최대 15건밤사이 공식 발표와 연구 업데이트를 넉넉히 반영합니다.
  2. 14:17오후 브리핑 · 최대 15건오전 이후 추가된 새 소식을 보충합니다.
  3. 20:17저녁 브리핑 · 최대 15건당일 마지막 업데이트를 전달합니다.

왜 정각이 아니라 17분인가?

GitHub Actions 예약이 몰리는 정각을 피하기 위한 운영값입니다. 예약 실행은 플랫폼 상황에 따라 몇 분 지연될 수 있습니다.

05

선별과 출력 품질

지정 Threads 계정은 가장 먼저 포함합니다. RSS와 키워드 후보는 출처별 최대 3건씩 번갈아 선택해 한 출처의 과도한 편중을 막습니다.

텔레그램 한 항목의 형식

1. 제목
핵심: 확인된 사실
왜 중요한가: 기술·산업적 의미
관련 대상: 직접 영향을 받는 구체적인 독자
출처: 원문 제공처
원문 링크

메시지 길이 처리

제목·요약·출처·URL을 묶어 보내되 한 메시지를 3,800자 이하로 유지합니다. 항목이 길면 여러 메시지로 안전하게 분할합니다.

06

보안과 배포

비밀값은 코드와 분리하고, GitHub Actions가 별도 서버 없이 예약 실행을 담당합니다.

  • 로컬 키 분리.env는 Git에서 제외
  • Actions SecretsTelegram 토큰·채팅 ID·Gemini 키
  • 최소 권한워크플로의 저장소 권한은 읽기 전용
  • 중복 캐시.data/seen.sqlite3만 Actions 캐시
  • 직렬 실행동일 브리핑의 중복 실행을 방지
  • 비공개 저장소개인 운영 설정 노출을 최소화
07

Threads 준비 상태

코드는 준비되어 있지만 운영 스위치는 꺼져 있습니다. 따라서 현재 자동 브리핑에는 Threads 게시물이 포함되지 않습니다.

권한 대기

우선 계정: choi.openai

계정 우선순위는 100으로 가장 높습니다. 활성화되면 최근 게시물을 가져오고, 작성자가 자신의 글에 이어 쓴 답글도 한 본문으로 합칩니다.

키워드 후보

AI agent, LLM, OpenAI, Claude, Gemini의 최근 게시물을 검색하며 하루 최대 4개 후보로 제한하도록 설정되어 있습니다.

다시 켜려면

Meta의 threads_profile_discovery 등 필요한 권한이 실제 앱에서 승인되어야 하고, 운영 토큰의 만료·갱신 방식을 관리해야 합니다. 이 작업이 번거롭다면 RSS 모드만으로도 봇은 정상 운영됩니다.

08

운영과 점검 방법

설정 확인과 시험 실행을 거친 뒤 실제 발송을 할 수 있습니다. 시험 실행은 텔레그램 전송과 중복 기록을 하지 않습니다.

로컬 점검

uv sync
uv run ai-trend-bot check-config
uv run ai-trend-bot run --dry-run --limit 15

실제 텔레그램 발송

uv run ai-trend-bot run --send --limit 15

09

제약과 다음 단계

개인용 무료 운영에는 충분하지만, 외부 서비스의 정책·형식·할당량에 영향을 받습니다.

예약 실행이 몇 분 늦을 수 있음

GitHub Actions cron은 정확한 실시간 스케줄러가 아닙니다. 개인 브리핑 용도에는 허용 가능한 지연으로 봅니다.

RSS 형식이 바뀔 수 있음

특정 출처가 응답 오류를 내면 경고만 남기고 다른 출처를 계속 처리합니다. 장기적으로는 실패 출처 알림이 유용합니다.

Gemini 무료 할당량 영향

할당량이 줄거나 모델명이 바뀌면 요약 단계가 실패할 수 있습니다. 필요하면 모델과 호출량을 설정값으로 조정합니다.

Actions 캐시의 영속성 한계

캐시가 사라지면 일부 과거 항목이 다시 후보가 될 수 있습니다. 사용량이 커질 때만 외부 데이터 저장소를 검토하면 됩니다.

Threads 권한과 토큰 관리

Meta 검수와 토큰 갱신 부담이 실제 가치보다 크면 계속 비활성화하는 것이 합리적입니다.

다음으로 해볼 개선

실패 알림, 소스별 일일 상한, 요약 톤 설정, 주간 회고 브리핑 순으로 확장하면 운영 가치가 큽니다.

현재 결론

추가 서버 없이 RSS 기반 봇을 운영할 수 있는 상태입니다. Threads는 필수 기능이 아니라 선택적 확장으로 남겨두었습니다.

이 문서는 저장소의 실제 설정과 구현을 기준으로 작성되었습니다.
설정값이 바뀌면 수집처·시간·상한도 함께 갱신해야 합니다.
